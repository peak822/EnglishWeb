# Google Translate TTS Integration Design

## Context
The English Study Web application currently uses the Web Speech API with a fallback to the Youdao dictionary API for text-to-speech functionality. The current approach suffers from inconsistent voice quality across devices and browsers, and the fallback API is not optimized for long texts. The user requested a 100% free solution that provides high-quality, consistent English voices for both short vocabulary words and long stories.

## Proposed Solution
Replace the Web Speech API and Youdao fallback completely with a custom integration of the Google Translate TTS API (`https://translate.google.com/translate_tts`). 

## Architecture & Components

### 1. Text Chunking Utility
- **Purpose**: Google Translate TTS limits requests to ~200 characters. To play long stories, text must be split into manageable chunks.
- **Logic**: 
  - Split text primarily by punctuation marks that represent natural pauses (`.`, `,`, `?`, `!`, `;`, `:`).
  - If a chunk still exceeds the character limit (e.g., 200 chars), split it by word boundaries (spaces) to ensure no words are cut off.
- **Input**: A full story string.
- **Output**: An array of string chunks.

### 2. Audio Queue Manager
- **Purpose**: To sequentially play the audio chunks generated by the chunking utility without perceptible gaps.
- **Mechanism**:
  - Maintain an array of audio URLs or a queue of text chunks.
  - Play the first chunk using the HTML5 `Audio` object.
  - Listen to the `onended` event of the `Audio` object to trigger the playback of the next chunk.
- **State Management**:
  - Keep track of the `currentAudio` instance to allow pausing or stopping playback.
  - When a user clicks "Stop", the queue must be cleared, and the `currentAudio.pause()` method called.

### 3. `audioService.js` Refactoring
- **Modifications**:
  - Remove all Web Speech API logic (`window.speechSynthesis`).
  - Remove Youdao API fallback logic.
  - Export unified methods: `speakText(text, options)` and `speakStory(text, options)`.
  - `speakText` will handle short words directly.
  - `speakStory` will utilize the Text Chunking Utility and Audio Queue Manager.

## Data Flow
1. User clicks the "play" button on a story or word.
2. The UI component calls `speakStory(text)` or `speakText(text)`.
3. `audioService.js` cleans the text (removes markdown, etc.).
4. If it's a story, it is passed to the chunker.
5. The chunker returns an array of strings.
6. The Queue Manager starts fetching and playing the audio for each string sequentially from `translate.google.com/translate_tts`.

## Error Handling
- If an audio chunk fails to load (`onerror` event), the Queue Manager should log a warning and proceed to the next chunk to prevent playback from halting completely.

## Testing Strategy
- **Unit/Manual Testing**:
  - Verify that a short vocabulary word plays correctly with a natural Google English voice.
  - Verify that a long story plays continuously without cutting off in the middle.
  - Verify that clicking "Stop" immediately halts playback and clears the queue, preventing subsequent chunks from playing.
